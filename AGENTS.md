# Architecture rules
- Keep avatar preference catalogs, the bundled preset catalog (`presets.ts`) and generation specification in the generate-avatar directory; preset images live in `public/avatars/presets` and profiles store their stable relative path so they load offline on Android and never use Supabase storage.
- Keep avatar request accounting server-only and transactional, separate from profile credit balances; it prevents duplicate generation/charging without replacing existing entitlements or storage ownership policies.
- Keep AI avatar provider-outage detection and its friendly text in `src/lib/avatarServiceErrors.ts` (mirrored by `AVATAR_SERVICE_BREAK_MESSAGE` in generate-avatar/generation.ts); users never see provider billing/key details and are sent to the presets tab instead. There is no illustrated or instant-avatar fallback: a failed generation leaves the avatar unchanged.
- Keep Winston chat and voice HTTP error mapping in `src/lib/winstonServiceErrors.ts` so quota/provider failures use clear, consistent user-facing messages.- Route Supabase reachability through `src/lib/backendHealth.ts` (fed by the client fetch wrapper); only a failed health probe may show the connection banner, so one flaky request never alarms users.
- Keep Google Play lifecycle email mapping, dedupe keys and refund/chargeback revocation decisions in `supabase/functions/_shared/googlePlayLifecycle.ts`; Premium removal itself runs only in the idempotent `apply_google_play_revocation` DB function before the RTDN upsert, and emails stay best-effort so they never affect Premium.
- Enforce one paid subscription per user via `src/lib/subscriptionGuard.ts` (client) mirrored in `supabase/functions/_shared/subscriptionGuard.ts` (paystack-init); manage/cancel actions follow the stored provider, never the device, to satisfy Play billing policy.
- Append `_shared/aiSafety.ts` rules (and crisis override on detection) to every text AI system prompt so harmful-content and crisis handling stay consistent.
- Ad placement rules (routes, launch grace, dialogs) live in `src/lib/ads/adPlacement.ts`; the app shows no banner ads (only rewarded and interstitial), so ads never cover content or interrupt core actions.
- Rewarded-ad Winston bonuses are granted only by `admob-ssv` after verifying Google's SSV signature, ad unit and a one-time session from `admob-reward` (logic in `_shared/admobSsv.ts`, idempotent `grant_winston_ad_reward`); the SDK reward callback is never trusted, and `consume_ai_message` adds the verified bonus server-side.
- Avatar Studio artwork is bundled in `src/assets/cosmetics` and keyed by cosmetic item id in `src/lib/cosmeticArt.ts`; `useCosmetics` maps stored categories/slots to Studio tabs (crown shows under Hats) so artwork never changes unlock rules or saved choices.
- Premium-gated UI reads entitlement only from `usePremium()` (server-written profile fields; the local premium cache is a per-user hint used only until the profile loads) and must show a neutral state while `entitlementLoading` is true; Premium perk cards derive lock state via `src/lib/premiumPreviews.ts`, so locks are never hard-coded or client-grantable.
